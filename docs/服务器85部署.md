# 172.29.20.85 官网工具集成

MBTI 通过官网同一端口的 `/mbti/` 路径提供服务。浏览器访问地址不带独立端口。

- 官网工具页：<http://172.29.20.85/tools>
- MBTI：<http://172.29.20.85/mbti/>
- 管理后台：<http://172.29.20.85/mbti/admin>
- 原服务器 <http://172.29.20.105:8086/> 继续使用独立的根路径构建。

官网“开放工具”卡片只有图标与“MBTI 人格测试”名称，使用相对链接 `/mbti/` 在当前标签页打开。官网源码位于 `/opt/lab-site/frontend`。

## 请求与运行结构

```text
浏览器 → 官网 80 端口 /mbti/
       → lab-site/frontend Nginx 去除 /mbti/ 前缀
       → mbti-site/mbti ClusterIP Service
       → 同一 Pod 内的 Nginx 与回环 API
       → mbti-site/postgres 独立数据库
```

MBTI Web 的 8086 仅用于集群内部通信，无 hostPort、NodePort 或外部服务。官网原有 `/api/` 仍访问官网后端，MBTI 的浏览器接口地址为 `/mbti/api/`，两者独立。`/mbti` 会保留查询参数并跳转到 `/mbti/`。

API 只监听 Pod 回环 `127.0.0.1:8091`。MBTI Nginx 信任当前节点 Pod 网段 `10.244.0.0/24` 的转发地址；官网覆盖客户端转发头，保留真实客户端地址用于限流。代理路径使用 MBTI 的安全响应头，支持二维码图片与报告导出，并关闭访问日志。

```text
/opt/mbti-site/
  .env                              权限 600 的实际密钥，不上传 Git
  current -> releases/v6-admin-policy-20261019
  releases/                         源码、前端产物、Kubernetes 配置
  backups/                          排除临时答案与后台会话的数据库备份
  rollback-v4/                      切换前清单、配置与私有环境备份
/srv/mbti-site/postgres/              独立 PostgreSQL 持久化目录
```

使用现有 Kubernetes / containerd，命名空间 `mbti-site`，节点 `lab-node`。PV `mbti-postgres` 使用 Retain 策略；PVC 为 `mbti-site/postgres`。10 Gi 为声明容量，本地卷不自动提供磁盘配额。迁移到其他集群时先修改节点、数据目录、可信 Pod 网段及官网代理的 Service 域名。

## 构建与发布

开发机执行子路径构建；路由、静态资源、API、续答链接和二维码均使用构建时的 BASE_URL。API 新增提交数据表，服务启动时会在现有数据库自动创建，不改动已有数据：

```sh
cd frontend
npm ci
npm run build -- --base=/mbti/ --outDir=dist-website85
```

普通 `npm run build` 仍构建根路径版本，供 `.105` 或独立站点使用。上传源代码、`frontend/dist-website85` 至新的 release 目录，再在服务器已有 Podman 中构建：

```sh
podman build --pull=never -t localhost/self-atlas-web:v6-admin-policy-20261019 \
  -f deploy/kubernetes/Dockerfile.web .
podman build --pull=never \
  --build-arg PYTHON_BASE=docker.io/library/self-atlas-api:v2-auto-next-20261016 \
  -t docker.io/library/self-atlas-api:v4-admin-policy-20261019 \
  -f deploy/Dockerfile.api .
podman save --format oci-archive -o /opt/mbti-site/mbti-web-v6-admin-policy.oci \
  localhost/self-atlas-web:v6-admin-policy-20261019
podman save --format oci-archive -o /opt/mbti-site/mbti-api-v4-admin-policy.oci \
  docker.io/library/self-atlas-api:v4-admin-policy-20261019
ctr -n k8s.io images import /opt/mbti-site/mbti-web-v6-admin-policy.oci
ctr -n k8s.io images import /opt/mbti-site/mbti-api-v4-admin-policy.oci
```

API / 初始化容器使用 `docker.io/library/self-atlas-api:v4-admin-policy-20261019`。数据库复用主机已有的 `localhost/lab-postgres:17` 镜像文件，账户、Secret、容器、卷和数据均独立。

官网 Nginx 的 server 块加入 [website-mbti.conf](../deploy/kubernetes/website-mbti.conf) 中的代理规则，并把工具链接设为 `/mbti/`。规则已合并到 `/opt/lab-site/frontend/nginx.conf`，随官网前端镜像发布。MBTI 与官网镜像都应先构建、校验并导入，再切换应用与官网入口。

私有 `.env` 格式为 `KEY=value`，不带 shell 引号：

```text
POSTGRES_PASSWORD=<随机十六进制>
DATABASE_URL=postgresql+psycopg://atlas:<同一数据库密码>@postgres.mbti-site.svc.cluster.local:5432/atlas
ADMIN_USERNAME=admin
ADMIN_PASSWORD=<至少 9 字符的独立随机密码>
SECRET_KEY=<至少 32 字符的独立随机密钥>
PUBLIC_ORIGIN=http://172.29.20.85,http://121.199.54.215:30001
COOKIE_SECURE=false
```

PUBLIC_ORIGIN 填浏览器来源，不含 `/mbti/`；多个来源以逗号分隔。官网内网地址与公网映射地址都需要加入，否则 GET 页面可用，但答卷提交和管理员登录等写请求会被来源校验拒绝。本次规则部署保留原数据库和加密密钥，并按要求重设现有管理员密码；初始密码环境变量不会覆盖已有管理员密码。真实密钥、Secret 导出、数据库和用户数据不上传 Git。

```sh
kubectl apply -f /opt/mbti-site/current/deploy/kubernetes/namespace.yaml
kubectl -n mbti-site create secret generic mbti-secrets \
  --from-env-file=/opt/mbti-site/.env --dry-run=client -o yaml | kubectl apply -f -
kubectl apply --dry-run=server -k /opt/mbti-site/current/deploy/kubernetes
kubectl apply -k /opt/mbti-site/current/deploy/kubernetes
kubectl -n mbti-site rollout status deployment/mbti --timeout=180s
```

官网部署本次镜像 `localhost/lab-frontend:mbti-path-20261016`。切换后删除先前 8086 的 firewalld 运行时及永久放行规则。保持官网现有的 80 端口规则。MBTI 部署使用 Recreate，切换期间会短暂不可用。

## 检查、备份与恢复

```sh
curl -f http://172.29.20.85/mbti/healthz
kubectl -n mbti-site get pods,services,pvc
kubectl -n mbti-site logs deployment/mbti -c api --tail=50
bash /opt/mbti-site/current/deploy/kubernetes/backup.sh
systemctl status mbti-k8s-backup.timer
```

`mbti-k8s-backup.timer` 每天北京时间 03:25 左右备份，排除 `resume_sessions` 和 `admin_sessions` 表数据。文件权限 600，留在主机 `/opt/mbti-site/backups/`。

先使用独立临时数据库验证备份。实际恢复前备份现状、暂停 MBTI 应用，保持 PostgreSQL 运行，且只恢复至 MBTI 数据库：

```sh
kubectl -n mbti-site scale deployment/mbti --replicas=0
kubectl -n mbti-site exec -i deployment/postgres -- \
  pg_restore -U atlas -d atlas --clean --if-exists --no-owner --exit-on-error < /path/to/atlas-backup.dump
kubectl -n mbti-site scale deployment/mbti --replicas=1
kubectl -n mbti-site rollout status deployment/mbti --timeout=180s
```

更新保留旧源码与镜像、先备份数据库。配置内容哈希会触发新 Pod。回退整次路径切换时，恢复官网前端镜像 / 配置、MBTI 旧清单与旧 PUBLIC_ORIGIN；如恢复旧 hostPort，还需恢复相应防火墙规则。保持 PVC、数据库目录和加密密钥，不删除持久卷。
