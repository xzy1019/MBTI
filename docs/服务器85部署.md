# 172.29.20.85 官网工具集成

本部署使用该主机现有 Kubernetes / containerd，独立命名空间 `mbti-site`。不运行专用 CentOS 主机的 `install-runtime.sh`，不创建第二个 Docker daemon。

- 官网工具页：<http://172.29.20.85/tools>
- MBTI：<http://172.29.20.85:8086/>
- MBTI 后台：<http://172.29.20.85:8086/admin>
- 原服务器 <http://172.29.20.105:8086/> 保留运行；两台主机的浏览器草稿、后台账号和续答数据各自独立。

官网在顶部主导航增加“开放工具”。`/tools` 采用响应式网格，每张工具卡片只有图标与名称，目前为“MBTI 人格测试”，在当前标签页跳转上述入口。官网前端源码位于主机 `/opt/lab-site/frontend`，本仓库仅存 MBTI 及其独立部署配置。

## 运行结构

```text
/opt/mbti-site/
  .env                              权限 600 的实际密钥，不上传 Git
  current -> releases/v3-server85-20261016
  releases/                         源码、前端生产产物、Kubernetes 配置
  backups/                          排除临时答案与后台会话的数据库备份
/srv/mbti-site/postgres/              独立 PostgreSQL 持久化目录
```

`deploy/kubernetes/` 为针对该单节点主机的清单：节点标签 `lab-node`，本地 PV 为 `mbti-postgres`、Retain 策略，PVC 为 `mbti-site/postgres`。10 Gi 为声明容量，本地卷不自动提供磁盘配额。部署到不同节点时，先修改节点标签、数据目录和 hostIP。

应用 Pod 内包含非 root Nginx 与 API。API 只监听 Pod 内回环 `127.0.0.1:8091`；Nginx 将 `172.29.20.85:8086` 映射到 Pod 的 8086 端口。数据库仅由集群内 Service 提供。初始化容器等待数据库 TCP 就绪，启动与就绪探针同时检查 API / 数据库。

复用已验证的应用镜像：

```text
docker.io/library/self-atlas-api:v2-auto-next-20261016
docker.io/library/self-atlas-web:v2-auto-next-20261016
localhost/lab-postgres:17
```

最后一个镜像是该主机已安装的 PostgreSQL 17 镜像，仅复用镜像文件；MBTI 使用独立容器、账户、Secret、卷和数据目录。镜像通过离线归档导入 `ctr -n k8s.io images import`，清单使用 `imagePullPolicy: Never`。

## 初次部署与更新

先备份官网，确认端口和目录未占用。创建 `/srv/mbti-site/postgres` 与私有 `/opt/mbti-site`，上传源码及镜像归档。创建 `.env`，格式为 `KEY=value`，不加 shell 引号，至少包含：

```text
POSTGRES_PASSWORD=<随机十六进制>
DATABASE_URL=postgresql+psycopg://atlas:<同一数据库密码>@postgres.mbti-site.svc.cluster.local:5432/atlas
ADMIN_USERNAME=admin
ADMIN_PASSWORD=<至少 16 字符的独立随机密码>
SECRET_KEY=<至少 32 字符的独立随机密钥>
PUBLIC_ORIGIN=http://172.29.20.85:8086
COOKIE_SECURE=false
```

不要将实际 `.env`、Secret 导出、数据库或服务器登录信息放进 Git。创建 namespace、私有 Secret，再校验并应用清单：

```sh
kubectl apply -f /opt/mbti-site/current/deploy/kubernetes/namespace.yaml
kubectl -n mbti-site create secret generic mbti-secrets \
  --from-env-file=/opt/mbti-site/.env --dry-run=client -o yaml | kubectl apply -f -
kubectl apply --dry-run=server -k /opt/mbti-site/current/deploy/kubernetes
kubectl apply -k /opt/mbti-site/current/deploy/kubernetes
kubectl -n mbti-site rollout status deployment/postgres --timeout=180s
kubectl -n mbti-site rollout status deployment/mbti --timeout=180s
```

firewalld 按官网现有内网范围增加 8086 TCP 规则：来源 `172.29.0.0/16`，同时写入运行时与永久配置。无需重载防火墙。首次启动创建初始题库和管理员；更新环境变量中的初始密码不会覆盖已有账号密码。

更新时为镜像设置新标签，同时修改初始化容器的 API 镜像。保留旧源码与镜像，备份数据库，切换 `current` 后应用对应目录。Nginx ConfigMap 使用内容哈希，配置修改会自动触发新 Pod。此单实例 hostPort 部署使用 Recreate，切换期间会短暂不可用。

## 检查、备份与恢复

```sh
curl -f http://172.29.20.85:8086/healthz
kubectl -n mbti-site get pods,services,pvc
kubectl -n mbti-site logs deployment/mbti -c api --tail=50
bash /opt/mbti-site/current/deploy/kubernetes/backup.sh
systemctl status mbti-k8s-backup.timer
```

安装 `mbti-k8s-backup.service` 与 `.timer` 后，每天北京时间 03:25 左右备份，权限 600，排除 `resume_sessions` 和 `admin_sessions` 表数据。备份只留在该主机 `/opt/mbti-site/backups/`。

先用临时数据库验证备份可恢复。实际恢复会替换 MBTI 数据库，须先备份现状，并暂停应用；不能恢复到官网数据库。恢复期间保持 PostgreSQL 部署运行：

```sh
kubectl -n mbti-site scale deployment/mbti --replicas=0
kubectl -n mbti-site exec -i deployment/postgres -- \
  pg_restore -U atlas -d atlas --clean --if-exists --no-owner --exit-on-error < /path/to/atlas-backup.dump
kubectl -n mbti-site scale deployment/mbti --replicas=1
kubectl -n mbti-site rollout status deployment/mbti --timeout=180s
```

回退应用使用旧 release 中的清单重新 `kubectl apply -k`；保持当前 PVC 和数据目录。不要删除 PVC / PV 或清空 PostgreSQL 目录。
